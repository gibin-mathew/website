How to use it

  1. Put the values you want to look up in list A. One per line, or upload a CSV and pick the column.
  2. Put the clean reference list in list B. That's the list you're matching against.
  3. Hit Match the lists. Every value in A gets its closest value in B and a score.
  4. Drag the threshold. Results re-sort instantly into match, review (up to 10 points below the threshold) and no match, so you can find the line where your data stops being trustworthy.
  5. Download the CSV. If list A came from a CSV, all its original columns are kept. If list B did too, B's columns are attached to each match. That's the fuzzy VLOOKUP part.

How the matching works

Before comparing anything, both sides are cleaned the same way: lower-cased, accents stripped, punctuation turned into spaces, and "&" read as "and". Common abbreviations are expanded, so "Corp" meets "Corporation" and "Univ." meets "University". Then each value is scored against the candidates in list B.

Smart is the default and the one I'd use. It compares word by word, and rare words count for more than common ones. If every name in your list ends in "Ltd", then "Ltd" says almost nothing, and Smart works that out from your own data. Numbers have to match exactly, so "Building 12" never matches "Building 13" just because the strings look alike. It then blends in whole-string edit distance, so typos like "Jonh Smith" still land on "John Smith".

The other methods are there when you know what you need:

  • Token sort sorts the words before comparing. "Data Science MSc" and "MSc Data Science" score 100.
  • Token set also ignores extra words, so "Data Science" scores 100 against "MSc Data Science". Useful, but it will happily over-match short names.
  • Edit distance counts how many single-character edits turn one string into the other. Best for typos in otherwise identical text.
  • Jaro-Winkler rewards matching starts. Good for short personal names.

For big lists the tool doesn't compare every pair. It builds an index of word fragments from list B and only scores the few dozen candidates that share the rarest fragments with each value. That's why 20,000 against 20,000 takes seconds instead of most of an hour.

Picking a threshold

There's no universal right number, and anyone who tells you otherwise hasn't looked at your data. Start at 85 with the Smart method, then open the review tab and read twenty rows. If they're mostly right, lower the threshold. If you see wrong pairs in matched, raise it. The review band exists so a person checks the borderline cases instead of the tool guessing.
